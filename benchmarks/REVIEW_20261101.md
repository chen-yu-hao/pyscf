## Measurement controls

The [driver](https://github.com/chen-yu-hao/pyscf/blob/4ed1ddc188d0a3160fb4d7e0254546ac21efd6e1/benchmarks/review_upstream.py)
runs one fresh process per sample in rotating variant order, without warm-up.
All four performance cases use RKS water clusters, def2-TZVPP, grid level 6,
two OpenMP threads, one BLAS thread, NUMA off, and the same CPU affinity.
The timer covers the complete `mf.kernel()`; imports, molecule construction,
validation and diagnostic counters are outside timing.
The memory limit is 2300 MB on both sides; the auditor requires equal in-core/direct choice.
SCF convergence uses `conv_tol=1e-9`, `max_cycle=80`, `direct_scf_tol=1e-13`.

Both source trees are built on the same Ubuntu 24.04/Python 3.12 runner with
GNU 13.3.0, `-O2 -DNDEBUG -fno-fast-math -ffp-contract=off`, OpenBLAS,
`BUILD_MARCH_NATIVE=OFF`, `USE_QCINT=OFF`, and XCFun disabled.
The trees share the exact libcint/Libxc installation; the auditor compares
library hashes, loaded BLAS hashes, package versions, effective threads and affinity.
This run installed NumPy 2.5.4, SciPy 1.18.1, h5py 3.16.0 and threadpoolctl 3.7.0.

“Default” preserves candidate option defaults. “Optimized” enables only
`PYSCF_DFT_DENSE_BLAS=1` and `PYSCF_DFT_MGGA_PACK_SIMD=1`.
AO/ERI caches, MGGA coalescing/scatter, tile screening and J/K prechecks are
not enabled in this performance matrix. Experimental options remain opt-in in the package.

## Numerical acceptance and independent verification

All **46** complete SCFs converged: 36 performance records plus 10 correctness records.
The latter cover MN15 n=2/cc-pVDZ/grid2 with control/legacy/fast/filtered ERI policy,
and MN15 n=4/def2-TZVPP/grid6 with those four plus coalescing and scatter variants.
The small ERI gate explicitly forces direct SCF; these single samples are correctness evidence.

The energy tolerance remained 1e-8 hartree; Ne/Exc/Vxc/J/K comparisons retained
`atol=1e-9, rtol=1e-10`. Every worker verified identical actual grid arrays.
The remote auditor reopened each saved NPZ and shared grid NPZ, verified hashes,
compared identical common density matrices and recomputed every matrix comparison.
Cached J/K also had to match a separate uncached optimizer; filter activation,
cache hits/budgets, and successful native XC dispatch were explicit assertions.
Coalescing/scatter additionally required successful sparse MGGA ncomp=4 dispatch.
Dispatch diagnostics run after timing; this is not a claim of zero fallbacks in every timed block.

## Source and CI findings resolved

- **TD scanner initial guess:** the first review run had upstream 3/3 pass and candidate 0/3.
  A scoped TD-only legacy guess now preserves ground-state projection and restores shared
  scanner settings on exceptions. The original three assertions pass unchanged in the benchmarked source.
- **Integration conflicts:** retain NUMA geometry reload plus compact payload behavior;
  combine J/K force, ERI cache and precheck CMake sources; retain the exact cumulative PR #6 MGGA source.
- **CI environment:** install threadpoolctl, apply platform-specific affinity conditions,
  preserve Linux NUMA tests, restore executable CI script modes, fix style failures, and pin
  the Python 3.9 Linux runner to supported Ubuntu 24.04.
- **ARM command quoting:** a green ARM build had not run pytest because nested shell quoting
  truncated the test command. Quoting is corrected and shell extraction validated; a real ARM rerun is pending.
- **macOS scratch-limit fixture:** without OpenMP, nocc=8192 requests exactly the 128 MiB cap
  and the strict greater-than guard permits the one-double sentinel to be read as a large array.
  The test now uses 8193, preserving return/sentinel assertions and production code.
  The extracted original C guard passed both no-OpenMP and eight-thread OpenMP checks without reaching BLAS.
